# 무료 사주 기본 정보와 유료 AI 풀이 준비

현재 공개 서비스는 무료 사주 기본 정보 확인을 제공하며, 유료 AI 풀이는 **판매 준비 중**이다. 출시 가격은 **1회 7,900원(최종 결제 금액)**으로 정했다. 아래 제공·실패 처리 기준으로 판매를 준비하며, 결제·전달·환불 연동을 완료하기 전까지 실제 결제를 받지 않는다. 테스트 결제가 승인되어도 풀이 접근 권한은 생기지 않는다.

## 출시 적용 기준 · 2026.09.30

이 절의 기준은 출시 시 적용할 서비스 약속이다. 현재 테스트 결제나 개발용 풀이에서 유료 제공·환불을 실행한다는 뜻은 아니다. 재생성·환불 처리, 고객지원 경로, 처리 상태 안내를 구현하고 검증한 뒤 판매를 활성화한다.

### 1회 제공 내용

- 8개 주제: **내 질문, 나의 기질, 일과 진로, 돈과 생활, 연애, 사람들과의 관계, 올해의 흐름, 다가오는 세 달**. 화면에서는 내 질문을 먼저 보여주며, 다른 장의 순서는 관심 주제에 따라 달라질 수 있다.
- 각 장에 **핵심 문장, 상세 풀이, 살펴본 사주 정보, 돌아볼 질문, 작은 실천**을 포함한다. 세 달을 다루는 장은 실제 계산된 세 구간의 근거를 각각 연결한다.
- 내 질문 장에서는 사용자가 적은 고민을 직접 다루고, 입력에서 확인한 상황과 사주 해석을 구분해 설명하며 선택 가능한 방향과 작은 실천을 제시한다. 고민을 적지 않았다면 선택한 관심 주제를 바탕으로 질문을 정한다.
- 글자 수나 페이지 수가 아니라 위 필수 구성과 질문 반영을 제공 기준으로 삼는다. 공개 예시의 분량은 읽는 길이를 가늠하는 사례이며, 모든 결과의 동일한 길이를 보장하지 않는다.
- 사주는 돌아볼 관점을 제공하는 전통 해석이다. 상대의 속마음, 재회·결혼·취업의 결과나 시기, 수익·질병 등 확인할 수 없는 사실을 보장하지 않는다.
- 추가 질문은 현재 개발 버전에서 한 풀이당 최대 5회, 생성 요청 시점부터 최대 24시간 안에 가능하다. 이 기간은 풀이 완성 시점부터 계산하는 기간이 아니다. 출시 전에 실제 이용 가능 기간과 구매자 접근 방식을 검증해 최종 안내와 일치시킨다.

### 전달 기한과 문제 발생 시 처리

| 상황 | 출시 시 적용할 처리 기준 |
| --- | --- |
| 정상 제공 | **서비스 서버에서 결제를 확인한 시점부터 15분 이내**, 필수 구성을 갖춘 풀이를 구매자가 열어볼 수 있게 한다. 결제 화면의 성공 표시나 작업 시작만으로 제공 완료 처리하지 않는다. |
| 생성 실패 또는 15분 초과 | 지연·실패 상태와 처리 방법을 안내하고, 고객이 **무료 재생성 또는 전액 환불** 중 선택할 수 있게 한다. 선택 없이 재생성을 반복하거나 완료된 것으로 처리하지 않는다. |
| 같은 구매의 중복 결제 | 결제사 내역과 주문을 대조해 중복 청구가 확인되면 **중복 청구분 전액 환불**. 정상 구매 한 건의 이용 권한과 구분해 처리한다. |
| 8장 또는 장별 필수 구성 누락, 내 질문을 다루지 않은 결과 | 고객이 **무료 보완·재생성 또는 전액 환불** 중 선택할 수 있게 한다. 문제를 확인한 결과를 완성본으로 계속 제공하지 않는다. |

위 내용은 서비스가 제공할 문제 해결 기준이며, 취소·환불에 관한 전체 약관이나 이용자 권리를 제한하는 문구가 아니다. 일반 취소, 환불 접수·처리 절차와 처리 기간은 판매 전에 별도로 안내하고 실제 지원 체계와 일치시킨다. 고객지원 경로가 없는 상태에서 환불 접수를 할 수 있는 것처럼 안내하지 않는다.

**현재 출시 차단 사유:** 실제 결제와 풀이 제공 연결, 지연·실패 감지 및 안내, 무료 재생성·보완의 주문 연결, 결제 취소·환불 실행과 상태 추적, 고객지원 접수 경로가 준비되지 않았다. 카카오 채널 심사 중이며 알림톡 발송·지원 경로로 작동한다고 안내하지 않는다. 구매한 풀이의 지속 보관·재열람 구현은 이번 변경 범위에 포함하지 않으며, 기존 판매 전 과제로 남긴다.

### 현재 코드가 검사하는 범위

`backend/app/yeoul.py`는 8장의 누락, 각 장의 핵심 문장·본문·근거·돌아볼 질문·작은 실천 필드, 실제 계산 자료에 존재하는 근거 ID, 세 달 각각의 근거, 반복 문단 등을 검사한다. 내부 품질 검사로 일반 장 본문 700자 이상·질문 장 1,000자 이상 등의 범위도 사용하지만, 이는 고객에게 보장하는 상품 분량이 아니다.

사용자 질문을 첫 문장부터 다루도록 생성 지침을 주고 있으나, 질문의 의미를 충실히 반영했는지는 현재 형식 검사만으로 보장되지 않는다. 출시 검수에는 실제 질문을 반영했는지 확인하는 절차와 누락 신고 처리도 포함해야 한다.

`backend/app/security.py`의 생성 작업 제한은 기본 **600초(10분)**이며 환경 설정으로 바꿀 수 있다. 이 제한은 AI 생성 작업에만 적용되고 결제 확인부터 열람까지의 15분 제공 기한을 집행하지 않는다. 15분 기준을 지키려면 결제 확인 시각을 저장하고 대기·재시도·검수·전달 시간을 합쳐 감시해야 한다. 실제 결제 후 기한 초과 처리나 자동 환불은 아직 구현되어 있지 않다.

## 구현된 범위

- `GET /api/v2/commerce/config`: 공개 준비 상태, 출시 가격(`price: 7900`), 결제 수단 준비 상태. `enabled`와 `fulfillment_enabled`는 항상 `false`다.
- 비회원 테스트 주문: 서버가 상품과 금액 7,900원을 결정한다. 테스트 주문도 공개한 출시 가격을 사용하지만 실제 청구나 유료 풀이 제공은 하지 않는다.
- SQLite 주문 원장: 주문별 비밀 토큰의 SHA-256 해시, 금액, 만료 시각, 결제 키, 상태를 저장한다. 생년월일·연락처·풀이 내용은 저장하지 않는다.
- 토스 테스트 승인: 주문 소유 토큰 확인 → 서버 금액 검증 → 결제 키를 주문에 고정 → 결제사 상태 조회 → 필요할 때 멱등 승인 → 재조회 → 주문/금액/통화/결제 키 검증 → `test_paid` 기록.
- 타임아웃 뒤에도 같은 주문과 같은 결제 키로 재확인한다. 새 주문을 자동 생성하거나 결제를 실패로 단정하지 않는다.
- 웹훅: `PAYMENT_STATUS_CHANGED` 알림을 받으면 주문에 이미 연결된 키를 사용해 토스 서버에서 다시 조회한다. 웹훅 본문의 결제 성공 주장으로 상태를 변경하지 않는다. 중복 알림은 중복 발급을 만들지 않으며, 취소 상태를 늦게 도착한 성공 응답으로 되돌리지 않는다.
- 기존 AI 전체 풀이 API는 로컬 개발자가 명시적으로 허용한 경우만 사용할 수 있다. `APP_ENV=production`에서는 이 개발용 우회 경로가 열리지 않는다.

## 기본 동작과 로컬 테스트 설정

설정이 없으면 주문 생성·승인·웹훅 API는 `503 CHECKOUT_NOT_AVAILABLE`을 반환한다. 현재 `.env`는 변경하지 않았다. 토스 계정을 만든 뒤 다음 값을 로컬 실행 환경에 설정해서 결제 연동을 검증할 수 있다.

```dotenv
APP_ENV=development
TOSS_TEST_CHECKOUT=true
TOSS_CLIENT_KEY=test_ck_<개별_연동_클라이언트_키>
TOSS_SECRET_KEY=test_sk_<개별_연동_시크릿_키>
COMMERCE_DB_PATH=/absolute/private/directory/commerce-test.sqlite3

# AI 전체 풀이를 로컬에서 따로 점검할 때만 설정
ALLOW_FREE_DEVELOPMENT_READINGS=true
```

DB 상위 폴더는 미리 만들어야 한다. 웹에서 서빙되지 않는 경로를 사용하고 파일 접근 권한과 백업을 관리한다. 테스트 원장은 전체 2,000건, 시간당 100건으로 제한된다. 테스트 원장 정리는 운영자가 직접 관리한다. 다중 서버 운영용 저장소와 보존 정책은 별도 구현해야 한다.

이 구현은 `test_ck_`/`test_sk_` 형태의 **개별 연동 테스트 키**만 허용한다. 라이브 키나 운영 환경에서는 테스트 체크아웃도 차단한다. 프런트엔드에는 시크릿 키를 전달하지 않는다. 준비 상태 UI는 출시 가격과 판매 준비 중 상태를 함께 표시하며, 실제 결제가 가능한 것처럼 안내하지 않는다.

## API 계약

| 요청 | 입력/인증 | 결과 |
| --- | --- | --- |
| `GET /api/v2/commerce/config` | 없음 | `enabled`, `product`, `methods`, `setup_required`, `development_readings_enabled` |
| `POST /api/v2/commerce/orders` | `{ "product_id": "premium-report" }` | `order_id`, `access_token`, 테스트 `client_key`, `amount`, `currency`, `expires_at`, `test_mode` |
| `GET /api/v2/commerce/orders/{order_id}` | `Authorization: Bearer <access_token>` | 비밀 토큰·결제 키를 제외한 주문 상태 |
| `POST /api/v2/commerce/orders/{order_id}/confirm` | 위 Bearer 헤더, `{ "payment_key": "…", "amount": 7900 }` | 검증된 테스트 상태. 성공해도 `report_access: false`, `fulfillment_status: "not_configured"` |
| `POST /api/v2/commerce/webhooks/toss` | `{ "eventType": "PAYMENT_STATUS_CHANGED", "data": { "orderId": "…", "paymentKey": "…" } }` | 결제사 재조회 뒤 수신 확인 |

주문 비밀 토큰은 URL·분석 이벤트·리퍼러·로그에 넣지 않는다. 결제 완료 페이지를 구현할 때 토스 리다이렉트의 `paymentKey`, `orderId`, `amount`를 읽고 URL에서 제거한 뒤, 보관한 주문 토큰과 함께 서버 승인 API를 호출한다. 브라우저 리다이렉트만으로 결제 완료 처리하지 않는다. SDK는 토스의 비회원 `ANONYMOUS` 방식을 사용할 수 있다.

토스페이·네이버페이는 심사를 마친 토스 계약에서 제공되는 결제수단으로 연결할 예정이다. 별도의 네이버페이 계약이 체결된 것처럼 표시하지 않는다. 실제 지원 수단은 가맹점 계약에 따라 달라진다.

## 실제 판매 전 필요한 다음 구현

현재 유료 전달용 PDF 생성·카카오 알림톡 발송·다운로드 링크를 발급하지 않는다. 공개 예시와 개발용 풀이의 텍스트 내려받기 및 브라우저 인쇄·PDF 저장은 제공한다. 결제 완료로 가장한 데모 다운로드는 제공하지 않는다. 실제 판매를 여는 변경에는 아래 사항을 함께 구현해야 한다.

1. 사업자와 도메인, 이용/환불 약관, 개인정보 보존 정책을 확정하고 PG 및 간편결제 계약을 완료한다. 가격은 정해진 1회 7,900원을 사용한다.
2. 주문과 사용자가 동의한 입력을 연결하고, 결제 완료·환불 상태에 따른 서버 측 리포트 권한 검사를 구현한다. 현재의 메모리 기반 AI 작업을 그대로 유료 발급 원장으로 사용하지 않는다.
3. 결제 상태 저장과 리포트 작업 등록을 한 트랜잭션으로 처리하는 outbox/영속 작업 큐를 추가한다. 발급·재시도·재시작·실패 알림·환불 처리까지 검증한다.
4. 8장과 각 필수 구성, 사용자 질문 반영을 검사하는 풀이 검수 및 비공개 저장소를 연결한다. PDF 파일 전달을 도입한다면 한글 글꼴을 포함한 PDF 렌더러도 검증한다. 글자 수를 상품 보장으로 추가하거나 현재 공개 예시의 길이를 일률적으로 약속하지 않는다.
5. 다운로드는 주문 권한 확인 후 짧게 만료되는 서명 URL을 발급한다. 카카오 전달은 승인된 비즈니스 채널/템플릿/발송 사업자와 수신 동의에 따라 연결한다. 생성 실패 시 돈만 받고 발급을 누락하지 않도록 복구 절차를 제공한다.
6. 결제 취소 API, 고객지원/환불 경로, 거래 대사, 재시도 가능한 웹훅 실패 처리, 계정 접근 제어, 공용 속도 제한을 준비한다. 결제 확인부터 15분 기한을 감시하고 실패·지연·중복 결제·필수 구성 누락에 대해 위 처리 기준을 실행한 뒤 실제 판매 활성화 코드를 별도로 추가한다.

## 검증

```sh
.venv-security/bin/python -m pytest tests/test_commerce.py -q
```
