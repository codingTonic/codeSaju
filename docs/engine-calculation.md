# 여울 원국 계산 기준과 출시 검증 범위

## 현재 제공하는 무료 원국

`POST /api/v2/chart`는 `backend/app/chart.py`에서 로컬 계산만 수행한다. Gemini 호출,
분석 태스크 생성, 결과 저장, 유료 AI 할당량 차감은 하지 않는다. 입력은 요청 본문으로만
전송하며 API 응답에 `Cache-Control: no-store`가 적용된다. 요청 제한기는 IP 원문 대신
해시와 시각만 보관하고, 프로세스당 20회/분·최대 4,096개 식별자로 제한한다. 여러 서버를
운영할 때에는 공통 프록시/저장소의 제한이 추가로 필요하다.

의존성은 프로젝트에 고정된 `lunar-python==1.4.8`이다. 이 라이브러리의 절기표는
베이징 시간 UTC+8 기준이다. 새 무료 원국은 한국 출생 시각을 UTC+9로 고정하여
다음과 같이 계산한다.

| 항목 | 구현 기준 |
| --- | --- |
| 양력 입력 | 실제 존재하는 Gregorian 날짜만 허용 |
| 음력 입력 | 월일 문자열을 직접 음력 라이브러리에 검증. 음력 2월 30일을 양력 날짜 검증으로 거부하지 않음 |
| 윤달 | 해당 연도에 존재하는 윤월만 허용. 양력에 윤달 표시 불가 |
| 연주 | 입력 양력 시각에서 1시간을 빼 UTC+8 절기표의 입춘 경계와 비교 |
| 월주 | 같은 환산 시각으로 절입 경계와 비교 |
| 일주 | 원래 입력 시각을 유지. `EightChar.setSect(2)`로 자정에 일주 변경 |
| 시주 | 원래 입력 시각 유지. 라이브러리 규칙에 따라 23시 시주 천간은 다음 일간 기준으로 계산 |
| 십성 | 원래 한국 시각의 일간을 기준으로 재계산. UTC+8 환산이 전날로 넘어가도 기준 일간을 바꾸지 않음 |
| 지지 | 본기 십성과 각 지장간 십성을 구분하여 반환 |
| 오행 | 보이는 천간·지지의 대표 오행을 각 1자로 집계. 지장간을 중복 합산하지 않음 |
| 대운 | 무료 원국에서는 계산하지 않음. 성별은 선택 입력이며 네 기둥 계산에 사용하지 않음 |
| 용신·신살 | `not_calculated`. 지원하지 않는 판단을 생성하거나 부족한 오행을 용신으로 대체하지 않음 |

### 시간 미상

정오는 달력 계산을 위한 임시값이다. API는 시주를 생략하고 `missing_pillars: ["시주"]`,
`time_known: false`를 반환한다. `solar_birth`에도 임시 정오를 실제 출생 시각처럼 넣지 않는다.

같은 한국 날짜의 00:00과 23:59:59에 연주·월주가 달라지는지 별도로 비교한다. 경계가
있으면 `uncertain_pillars`에 `year`/`month`를 넣고 해당 기둥에 `estimated: true`를 표시한다.
이 경우 `element_counts_estimated: true`이며 `element_note`는 해당 십성과 오행 수치도
출생 시각에 따라 달라진다고 설명한다. 화면에서 추정 표시를 숨기거나 정오 결과를 확정값으로
설명해서는 안 된다.

### 자동 검증한 경계 사례

`tests/test_chart.py`의 고정 사례는 현재 라이브러리 표에 대한 구현 검증이다. 독립적인
한국 공식 역서 전체와 일치함을 증명하는 검증은 아니다.

- 2000년 입춘: 라이브러리 UTC+8 `2000-02-04 20:40:24` → 한국 시각 `21:40:24`.
  21:40의 기묘년·정축월과 21:41의 경진년·무인월을 구분한다.
- 2000년 경칩: UTC+8 `2000-03-05 14:42:40` → 한국 시각 `15:42:40`.
  15:42의 무인월과 15:43의 기묘월을 구분한다.
- `2000-03-05 00:30`: 절기 비교 시각이 전날로 넘어가도 일주는 임술로 유지한다.
  연간 경금의 십성은 원래 임수 일간 기준 편인이다.
- `2000-03-05 23:30`과 다음 날 `00:30`: 일주는 임술→계해로 바뀌고
  라이브러리의 야자시 규칙에 따라 시주는 임자로 유지된다.
- 음력 `2000-02-30`과 양력 `2000-04-04`의 원국 일치, 존재하는 윤달과
  존재하지 않는 윤달, 음력 환산 생일 기준 만 18세 경계, 시간 미상의 입춘·경칩을 검증한다.
- AI 설정이 없어도 응답하고 분석 태스크/AI 제한기를 사용하지 않으며, 무료 조회 제한기의
  메모리 상한·만료 회복을 검증한다.

## 기존 상세 리포트 엔진의 별도 한계

`backend/app/saju.py:build_saju_profile`은 기존 상세 리포트와 예시 데이터의 계산 경로다.
새 무료 원국과 완전히 같은 버전으로 간주해서는 안 된다.

| 항목 | 기존 상세 리포트의 상태 |
| --- | --- |
| 출생 연주·월주 | 입력 시각을 UTC+8 절기표와 그대로 비교. 실제 한국 입춘·절입 주변 1시간에서 새 무료 원국과 다를 수 있음 |
| 월운 경계 표시 | 라이브러리 UTC+8 경계 시각을 그대로 반환하지만 기존 표시가 한국 표준시로 설명하는 문제가 있음 |
| 대운 | 원래 Lunar 객체에서 방향·월주·기산값을 얻으며 기본 `Yun` sect=1의 시진 단위 규칙을 사용 |
| 음력 입력 모델 | `ReadingRequest.birth_date`가 Gregorian `date`이므로 유효한 음력 2월 30일을 받지 못함 |

출생 연주·월주만 고치면 대운의 방향·출발 월주와 서로 다른 값이 남을 수 있다. 단순히
UTC+8 변환 객체를 `Yun`에 넘기는 방법도 현재 sect=1의 시진 구간, 자정·연말 경계에서
대운 시작일·나이를 함께 바꿀 수 있어 독립 검증이 필요하다. 이번 무료 원국 추가에서는
기존 상세 엔진을 부분 변경하지 않았다.

기존 입력 화면으로 날짜를 넘겨야 한다면 무료 원국의 `profile.solar_birth`에 있는 양력
날짜를 사용하고 `calendar_type: "solar"`, `is_leap_month: false`로 명시할 수 있다.
이는 음력 2월 30일 입력 제약만 해결하며 절기·대운 계산 차이는 해결하지 않는다.

## 정밀 계산을 표방하기 전 필요한 작업

1. 한국 공식 음양력·절기 기준의 독립 검증표를 확보하고 1900년 이후 전체 지원 기간의
   변환, 윤달, 자정 주변 합삭과 절입, 드문 한국·중국 음력 차이를 대조한다.
2. 출생지와 과거 표준시·서머타임 적용 정책을 정하고 검증한다. 현재는 모든 입력에
   UTC+9를 고정 적용하며 경도·진태양시 보정은 제공하지 않는다.
3. 무료 원국과 상세 리포트가 공통 출생 달력·기둥 계산 결과를 사용하도록 통합한다.
   원국, 월운 시각, 대운 방향·기산 방식·시작일·나이를 한 번에 검증하고 버전을 올린다.
4. 양력 `date`와 음력 월일 입력을 공통 모델에서 구분하고 실제 음력 날짜를 검증한다.
5. 명확한 학파/계산 규칙과 독립 검증 없이 용신·신살·신강·신약을 자동 확정하지 않는다.

현재 제품 표현은 **계산 기준을 공개한 참고용 원국**으로 제한한다. 정밀 만세력 전체 검증,
한국 역서 완전 일치, 사건 예측 정확도 또는 1초 응답 보장은 제공하지 않는다.
